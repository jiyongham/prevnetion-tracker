# prevention-tracker

인프라 장애예방 활동의 진척을 자동 집계하고 주간 Teams 리포트를 발송하는 웹서비스.

## 관리 대상 (3개 도메인)

| 도메인 | 내용 | 화면 |
|---|---|---|
| **DR훈련** | DR 모의훈련 (실전환 / 무중단) | `/` |
| **용량관리** | 임계치 초과 DB 디스크 증설 (DATA / ARCH) | `/capacity` |
| **EoS** | 노후 OS/DB 버전 업그레이드 및 IP 전환 | `/eos` |

## 기술 스택

- **Backend**: Python + FastAPI + Jinja2
- **DB**: SQLite (엑셀 원본에 없는 웹 입력값·변경이력·발송 스냅샷)
- **Scheduler**: APScheduler
- **알림**: Teams Incoming Webhook (채널) / Graph API (개인 DM)
- **AI**: 사내 LLM Agent Gateway

## 데이터 흐름

```
엑셀(대상 목록)  ─┐
JIRA (변경 티켓)  ├─→  매칭·완료 판정  →  대시보드 / 주간 Teams 리포트
CMDB (Insight)   │
Confluence(주간계획)│
Polestar (EMS)   ─┘
```

- **엑셀**: 반기별 대상 목록 원본. 대상 여부(O/X), 일정, 담당자 등.
- **DB**: 웹에서 수정한 값이 엑셀보다 우선. 원본은 건드리지 않음.

## 외부 연동

| 시스템 | 용도 |
|---|---|
| JIRA REST API | 변경 티켓 조회 (`[예방1]`/`[예방3]`/`[예방4]` 태그) |
| JIRA Insight/Assets | CMDB 자산 조회, 담당자 대조 |
| Confluence REST API | EoS 주간 작업계획 페이지 파싱 (금주 실적) |
| Polestar (EMS) | CI 이름의 `_OLD` 접미사로 전환 완료 확인 |
| Teams Webhook / Graph | 리포트 발송, 미계획 담당자 DM |

## 완료 판정

도메인마다 "무엇을 완료로 볼 것인가"가 다르다. **계획일이 지났다는 것만으로는 완료로 보지 않는다** — 그렇게 세면 실제 수행치보다 크게 부풀려진다.

- **DR훈련**: 해당 반기 안의 실전환(`[예방3]`) 티켓 우선, 없으면 무중단 티켓. 또는 엑셀/웹 완료 표기.
- **용량관리**: 증설 완료 표기 또는 해당 반기 티켓.
- **EoS**: 아래 둘의 **합집합**
  - JIRA `작업 완료(CMDB)` 필드에 `_OLD`로 끝나는 자산이 있는 티켓 (Insight Key로 정확 매칭)
  - Polestar CI 이름이 `_OLD`로 바뀐 대상 (전환 완료 시 AS-IS 자산명에 `_OLD`가 붙는 규칙)

반려/중단/종료 상태의 티켓은 완료 근거에서 제외한다.

### 대상 매칭

티켓과 엑셀 대상을 잇는 키는 IP / 호스트명 / CMDB Insight Key. EoS는 CMDB Key 매칭을 우선하고, 그 필드가 없는 티켓만 IP·호스트명으로 보강한다.

## 주간 Teams 리포트

목요일 자동 발송 (`.env`로 조정).

| 리포트 | 시각 | 비고 |
|---|---|---|
| DR훈련 | 09:00 | |
| 용량관리 | 09:00 | |
| EoS | 17:00 | 담당자가 목요일 중 Confluence 주간계획을 작성하므로 그 이후 |

발송 직전 지난 발송분(`report_snapshot`)과 비교해 **이상 징후를 점검**한다. 완료 대수 감소, 진행률 급변, 전체 대상 변동 등을 규칙으로 감지하고, 해석만 AI 에이전트가 맡는다. 이상이 있어도 정기 보고라 발송은 막지 않고 서버 로그에 경고를 남긴다.

## AI 에이전트

계산·판정은 코드가 하고, 서술과 해석만 에이전트에 맡긴다. 에이전트에 목록을 자유 생성시키지 않고 후보를 주고 고르게 해서 없는 시스템을 지어내는 것을 막는다.

| 용도 | `.env` 키 |
|---|---|
| 담당자 조회 챗봇 (DR훈련) | `AGENT_ID` / `AGENT_CODE` |
| 주간 특이사항 요약 | `SUMMARY_AGENT_ID` / `_CODE` |
| 매칭 실패 원인 진단 | `DIAGNOSE_AGENT_ID` / `_CODE` |
| 리포트 이상 징후 해석 | `REPORT_CHECK_AGENT_ID` / `_CODE` |
| 용량관리 산정 기준 설명 | `CAPACITY_CALC_AGENT_ID` / `_CODE` |
| 용량관리 진척 조회 | `CAPACITY_STATUS_AGENT_ID` / `_CODE` |
| EoS 진척 조회 | `EOS_STATUS_AGENT_ID` / `_CODE` |
| EoS 차주 계획 파악 | `EOS_PLAN_AGENT_ID` / `_CODE` |

미설정이면 해당 기능만 조용히 생략되고 나머지는 정상 동작한다.

## 주요 기능

- **인라인 편집**: 일정·완료·증적·비고·담당자를 표에서 바로 수정, 변경이력 자동 기록
- **관리자 기능**: 입력자명이 관리자 목록에 있을 때만 노출 (완료 체크, 제외 처리, 리포트 수동 발송)
- **제외 처리**: 수행하지 않기로 확정된 대상을 목록에서 분리, 복귀 가능
- **미계획 리마인드**: 일정 미등록 담당자에게 Teams DM (미리보기 후 발송)
- **담당자 확인**: 엑셀 담당자와 CMDB 등록 담당자 불일치 대조
- **챗봇**: 각 대시보드에서 본인 대상·진척 조회

## 실행

```bash
cp .env.example .env      # 각 값 채우기
pip install -r requirements.txt
uvicorn app.main:app --reload
```

`.env`는 gitignore 대상이며 모든 인증정보·에이전트 키가 여기 들어간다. k8s 배포 시 Secret과 반드시 함께 갱신해야 한다 (한쪽만 배포되면 설정 로딩에서 실패).

## 참고

- 리포트의 모수(전체 대상 수)는 착수 시점 고정값을 쓰는 경우가 있다. 엑셀 행 수와 다를 수 있으며 `.env`로 관리한다.
- 반기 경계(H1: 1~6월, H2: 7~12월)를 넘는 완료는 인정하지 않는다. 연 1회 수행이 원칙이라 해당 반기 안에서 끝난 것만 센다.
